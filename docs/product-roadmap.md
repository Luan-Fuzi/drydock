# 产品 roadmap

> 2026-10-03 依 D24/D25 定调制定。[prototype-plan.md](prototype-plan.md) 的六步计划（步骤 1–5 判据全绿、步骤 6 真机周进行中）是本文前身；步骤 6 收尾后按本文推进。

## 总策略：功能先行，集中测试

**先把 D25 定调的功能全集实现到「当前可用」状态（含用户界面与调试入口），再进入集中测试期找缺陷、做 Q2 需求验证**（2026-10-03 用户拍板）。理由：agent 辅助下实现速度快，半成品拿去实测的数据失真——缺输入手势或文件桥的版本测不出真实留存。已知代价：需求误判的发现时点后移；非商业、自用导向下可接受，若 Q2 结论为负，沉没的是工程时间而非市场机会。

两个前提：

- **Q1 结论是总开关**：结论为负则本文作废，走 [open-questions.md](open-questions.md) 转向预案（遥控器型产品）。阶段 0 与阶段 1–4 **并行推进**（2026-10-03 调整：其剩余项为使用侧观测而非工程任务），但 Q1 verdict 必须在阶段 5（集中测试、朋友实测 APK）之前收口。
- **「所有功能」= D25 清单封顶**：范围由 D25 与 decisions.md 不做清单界定（agent 无关、首启三步、文件互通前三档、端口面板、输入增强），不因「先做完再测」扩张范围。

每阶段仍带开发期自验判据（判据即停机点的惯例不变）；集中测试期做整体验收。真机纪律、git 纪律照 [AGENTS.md](../AGENTS.md) 执行，产品期 APK 仍只从 main tag 构建。

## 阶段 0：真机周收尾（进行中，与阶段 1–4 并行）

欠：S3 发热降频人工评估；proot 楔死在 agent 长任务下的观测；Q1/Q7 周尾结论（tag `q1-verdict`）。Q7 已收敛（D25 开源硬前提）：Termux fork 确认性实测 + proot 性能基线，不再承担选型职能。剩余项均为使用侧观测（日常真用中记录发热与异常，真机纪律照旧：正式采样不插线），不占工程时间，随阶段 1–4 开发自然积累。

判据：Q1 verdict 入册（2026-10-03 调整：不作为阶段 1 的开工门槛，改为阶段 5 的准入门槛）。

## 阶段 1：产品首页与首启向导

内容：主页重做——一键进终端为主面，现有判据仪器收进开发者入口（不删，调试接口保留）；首启向导三步（保活强引导 → 协议/Base URL/API Key → agent 配方）；配方系统——OpenCode、pi 的安装脚本 + 端点注入 + 模型环境变量模板，Claude Code 不进默认引导；「agent 是配置器」的首启 motd / 终端内引导脚本。

判据：新用户从装上 APK 到终端里 agent 出第一句话，全程不需要理解 Linux 概念；向导逐步可跳（保活除外），每条跳过路径都能到达同一终点。

## 阶段 2：终端输入

内容：虚拟键条扩展（Ctrl 组合一般化、Shift+Tab、PgUp/PgDn）；触控手势层——点按保持聚焦拉起输入法、双击或专用键发回车、长按进选区（xterm buffer 范围高亮 + 复制/粘贴浮钮）；IME 拼音组合输入真机验证（AV2 遗留项）。

判据：真机上单手完成 OpenCode 或 pi 的一个完整操作回合（进菜单、选中、提交）。

**状态（2026-10-03）**：AVD 可验部分完成——键条扩至 11 键（Ctrl 粘滞/Esc/Tab/⇧Tab/PgUp/PgDn/四方向/显式回车，横向可滚）、双击终端区发回车、单击保持聚焦拉输入法；CDP 断言过（键数、回车注入、Ctrl 粘滞一次合成无递归）。触控手感、IME 拼音组合、长按选区交互留真机/视觉批次。

## 阶段 3：文件边界与端口面板

内容：DocumentsProvider 将 workspace 提供给全安卓文件选择器；注册系统分享目标 + SAF 文件选择器传入；产物保存/导出的界面化（沿用 I4 通道，行文按 D25 术语规范）；端口面板——解析环境内监听端口，一键用系统浏览器打开（proot 不隔离网络，架构上已免费）。直通绑定（proot -b）为默认关闭的高级选项，任意目录双向同步不做。

判据：系统文件选择器可见 workspace 文件（微信发送附件场景）；从微信分享一个 zip 进 Drydock，agent 处理后产物在 Downloads/Drydock 可见。

**状态（2026-10-03）**：AVD 全过——SAF 选择器出现「Drydock workspace」根、目录可浏览、文件可选并导入 Inbox；分享目标（文本/文件）导入 Inbox 实证；端口面板以本地 connect 探活（/proc/net/tcp 对 app 域被 SELinux 屏蔽，实测改法），活会话端口带「（终端）」标注实证，非终端端口配「浏览器打开」按钮。微信真实分享链路留真机。
**状态增补（2026-10-04 夜批）**：文件页 ACTION_VIEW 甩系统应用实证（logcat START 判据，Resolver 消费，t2）；WorkspaceProvider 补齐 deleteDocument/renameDocument（flags 原本声明而方法缺失=SAF 消费方崩溃路径）并经 app 进程全回路自测（写→读→改名→列举→删除，t6）；直通绑定第三档最小版落地并双向实证（固定 Download ↔ /root/AndroidDownload，默认关，t10；口径与代价见 D28-3）。

## 阶段 4：可靠性与运营面（与阶段 2/3 并行推进）

内容：救援通道（Q8：宿主绕过 ttyd 起最简 PTY、rootfs 完整性校验、快照回滚，判据细化时定）；存储优化——apt/npm 缓存清理、agent 层按需安装（不装 agent 时整机约 130 MB）；rootfs 与配方的版本升级路径；分发渠道结论（商店政策对运行时下载可执行代码的限制，非商业阶段侧载无碍但需明文）。

判据：rootfs 受损后可自救；不装 agent 的存储占用实测入册。

**状态（2026-10-03，本阶段可做项全部收口）**：救援通道 MVP 及受损自救最小场景实证——毒化 dpkg status（dpkg 全盲）→ 经 RescueActivity 界面修复（status-old 恢复）→ dpkg 复验健康；更深损坏形态（rootfs 结构性损坏）如实计为未验，留 Q8 产品期。存储实测入册（`draft/phase4-avd-verdict.json`）：不装 agent 的 app 数据装机即用态 438 MB，大头是 apt 索引与二进制缓存（合计约 317 MB），净底盘 121 MB；缓存清理已改打真目标（pkgcache + lists），清后实测 121 MB。版本升级路径与分发渠道结论入册 D26（旁路部署 + 原子切换；GitHub Releases 侧载，不做商店上架承诺）。
**状态增补（2026-10-04 夜批）**：环境导出 + 卸载强提醒落地（口径收窄为工作区与配置，全环境 ~2GB 不可行；排除 .l2s/.npm/绑定目录，MediaStore 落 Downloads/Drydock 流式写入，t9 拉回抽查实证）；多密钥管理与会话级注入落地（KeyVault，t8；**2026-10-05 随 D29 删除**）；终端页内菜单最小版落地（t11）；配套缺陷修复见 D28。

## 阶段 5：集中测试期

内容：自用缺陷扫荡；Q2 需求验证——装给 2–3 个不懂终端的朋友，什么都不教，一周后看使用痕迹（判据见 open-questions.md）；Q3 OEM 保活矩阵按手头机型积累；缺陷修复循环。

判据：Q2 结论入册（正负均触发产品层复盘）；已知缺陷收敛到可接受基线。
